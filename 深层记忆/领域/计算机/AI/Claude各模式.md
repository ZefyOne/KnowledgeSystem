### Claude各模式详解

#### 1. Plan Mode（计划模式） 🔍
- **核心行为**：Claude 不直接执行任何操作，而是先探索上下文、分析需求，然后制定详细的实施计划展示给你
- **适用场景**：
  - 复杂的多步骤任务（如架构重构、新功能设计）
  - 需要你提前确认方案再动手的场景
  - 涉及多个文件、可能产生重大影响的修改
- **工作流程**：`理解需求 → 探索代码 → 制定计划 → 你审核批准 → 执行`
- **界面标识**：输入框左侧显示 🔍 图标
- **优点**：安全可控，避免方向性错误
- **缺点**：需要你介入确认，速度较慢

#### 2. For Shortcuts（默认模式）⚡
- **核心行为**：AI 自主判断当前任务的复杂程度，简单任务直接执行，复杂任务先询问你的意见
- **适用场景**：
  - 日常开发和笔记管理（推荐大多数场景使用）
  - 需求明确但不确定是否有歧义的任务
  - 希望兼顾效率与安全的一般性工作
- **判断标准**：
  - 简单修改 → 直接执行
  - 需要决策/有歧义 → 先提问再执行
- **优点**：效率与控制的良好平衡
- **缺点**：偶尔会问多余问题或跳过必要的确认

#### 3. Accept Edits On（自动编辑模式）✏️
- **核心行为**：所有文件修改自动写入，不再逐处询问"是否应用此编辑"
- **适用场景**：
  - 批量替换和重构（如重命名变量、格式化代码）
  - 确定性很强的修改（如按模板创建一系列笔记）
  - 你已经完全清楚要改什么，不需要逐项确认
- **行为变化**：仍会展示修改内容（可通过其他设置关闭），但不再暂停等待你点"接受"
- **优点**：效率最高，适合大规模操作
- **缺点**：控制最少，修改自动生效，出错后需要手动回滚

---

> 💡 **建议**：日常使用保持默认模式。需要谨慎操作时切换到 Plan Mode，需要批量处理时切换到 Accept Edits On。三种模式可以在聊天过程中随时通过 `Shift+Tab` 切换。

### 第四种方式：免确认模式（CLI 启动参数）🚀

在终端启动 Claude Code 时加上 `--dangerously-skip-permissions` 参数，**完全跳过所有权限确认弹窗**：

```bash
claude --dangerously-skip-permissions
# 或简写
claude -p
```

- **核心行为**：所有操作直接执行，不弹出任何权限确认窗口（读文件、写文件、执行命令等）
- **适用场景**：
  - 完全信任当前任务的自动化脚本
  - 批量处理大量文件，逐一点确认太繁琐
  - CI/CD 或自动化流程中调用 Claude
- **工作流程**：`启动 → 所有操作自动放行 → 完成`
- **优点**：完全无打扰，效率最大化
- **危险**：⚠️ **极度不安全** — Claude 可以自由执行任何命令、读写任何文件、修改系统配置，没有中间拦截
- **建议**：仅用于一次性明确任务，用完即关。不在需要长期工作时使用此模式。
- **注意**：这并非聊天中的模式切换，而是**启动时的命令行参数**，需要在终端中手动输入。

> ⚠️ **警告**：这个参数的名字就叫 `dangerously-skip-permissions`，官方已经把风险写在名字里了。使用前请确保你清楚自己在做什么。
